# Skenario Uji K-01–K-08 (level HTTP, berlaku web + Android)

Setiap skenario memakai endpoint di `../contract/endpoints.json`.
"Server" = backend aktual. Kedua platform wajib lolos semua yang bertanda ✅.

## K-01 — Akun instruktur hanya via undangan admin

1. `POST /auth/register {role: teacher}` → peran diabaikan, kalaupun ada
   akun yang lahir selalu `student` (UI wajib menolak pilihan teacher).
2. Admin `POST /admin/invitations {email, nama}` → 201 + `inviteUrl`.
3. `GET /invitations/validate?token=` → 200 (data undangan, tanpa hash).
4. `POST /invitations/accept {token, password}` → 201 + sesi teacher.
5. Token sama dipakai lagi → 409 (satu kali pakai). ✅

## K-02 — Kuis tanpa batas, nilai terbaik, lulus bertahan

1. `POST /materials/:id/quiz-attempts` skor 60 (ambang 70) → `passed:false`.
2. Ulangi, skor 80 → `passed:true`, `bestScore:80`, `overallPassed:true`.
3. Ulangi, skor 50 → tetap `passed` record itu `false`, TAPI
   `GET .../quiz-best` → `passed:true`, `bestScore:80` (lulus bertahan). ✅
4. `GET .../quiz` tidak pernah memuat `isCorrect`/`explanation`.

## K-03 — Voucher resmi sekali pakai anti-race

1. Admin buat voucher personal untuk user A + kursus C.
2. A `POST /vouchers/redeem` → 201 + akses (`GET .../access` true).
3. A redeem lagi → 409. User B redeem kode A → 403.
4. Admin disable → redeem → 403; enable → pulih sesuai kuota.
5. Diskon: `POST /vouchers/validate` tidak menghanguskan; hangus atomik
   hanya saat `POST /admin/payments/:id/verify` terima. 5 request paralel
   pada `maxUses=2` → tepat 2 sukses. ✅

## K-04 — Materi biasa selesai via Berikutnya

1. `POST /materials/:id/progress` materi biasa → `completed:true`.
2. Ulangi → `alreadyCompleted:true` (idempoten, satu baris).
3. `GET /me/progress?courseId=` memuat id tersebut (refresh tidak hilang). ✅
4. Berikutnya TIDAK meluluskan kuis/tugas (lihat K-02/K-06).

## K-05 — Sertifikat modul otomatis bersyarat

1. Modul 1 materi wajib belum lengkap → `POST /modules/:id/certificate`
   → 403 `NOT_ELIGIBLE` + `failReasons` tidak kosong.
2. Lengkapi semua (progres + kuis lulus + tugas lulus) → sertifikat terbit
   otomatis (respons progres/kuis/grade memuat `certificateIssued:true`).
3. `GET /me/certificates` memuatnya; unduh PDF 200.
4. `GET /certificates/verify/:code` publik → data minimal benar.
5. Cabut (alasan ≥5 char) → verify tampil `revoked`; terbit ulang → 409. ✅

## K-06 — Tugas kumpul ulang + rubrik server

1. Submit PDF → 201 baris baru; submit lagi → baris baru (riwayat utuh).
2. Nilai dengan rubrik `{kelengkapan, ketepatan, kerapian}` → skor akhir
   = rata-rata server (skor kiriman diabaikan).
3. `GET .../submissions/status` → `passed` menempel walau kiriman
   berikutnya belum dinilai; belum lulus = belum penuhi sertifikat. ✅

## K-07 — Modul independen, sekuens hanya dalam sub-modul

1. Dengan akses kursus, materi modul mana pun dapat dibuka langsung
   (server tidak mengunci antar-modul).
2. Aplikasi mengunci materi berikutnya dalam sub-modul yang sama sampai
   materi sebelumnya selesai (aturan tunggal, tanpa daftar manual). ✅

## K-08 — Ubah materi aman + tercatat resmi

1. Buka editor → catat `updatedAt` sebagai cap dasar.
2. Ubah materi di sesi lain → simpan dari editor lama tanpa cap baru
   → `PATCH` tanpa `expectedUpdatedAt` yang cocok → 409
   `MATERIAL_CONFLICT` + `data.currentUpdatedAt`.
3. Simpan ulang dengan cap terbaru + `changeSignificance` +
   `changeReason` → 200 + entri audit.
4. `GET /materials/:id/changes` memuat riwayat (aktor, waktu, field,
   signifikansi, alasan). ✅
5. Progres peserta tidak terhapus oleh PATCH materi apa pun.
